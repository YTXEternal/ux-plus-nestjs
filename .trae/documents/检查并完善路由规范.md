## 已发现的问题（基于 api-specification.md#L1-26）

* Swagger 不完整：`GET /api/v1/auth/list` 缺少 `@ApiOperation/@ApiResponse` 等描述（[auth.controller.ts](file:///d:/data/development/Projects/NestJS_React_StoreManagement/ux-plus-nestjs/src/routes/auth/auth.controller.ts#L89-L95)）。

* Swagger 安全标记不一致：由于 Swagger 插件对 `/auth/*` 路径默认不加 bearer security，`/auth/list` 在文档里会显示“不需要 Token”，但实际会被全局 `AuthTokenGuard` 拦截（401）。

* Controller 请求参数未统一 DTO：多处详情接口使用 `@Param('xxx')` 原始类型，而规则要求“使用 DTO 定义接口请求参数”（示例：[sys-user.controller.ts](file:///d:/data/development/Projects/NestJS_React_StoreManagement/ux-plus-nestjs/src/routes/system/user/sys-user.controller.ts#L49-L56)）。

## 实施方案（会改动哪些地方）

1. 完善认证路由文档与安全声明

   * 为 `GET auth/list` 增加 `@ApiOperation`、`@ApiSwaggerResponse`。

   * 为该接口显式声明 bearer 鉴权（只对该方法加），保证 Swagger 与实际行为一致。

2. 将所有 Path 参数改为 DTO 入参

   * 在各模块 `dto/` 下新增对应的 `ParamDto`（例如 `GetUserParamDto { userId: number }`），补齐 `class-validator` 校验与 `@ApiProperty(example)`。

   * 将 Controller 方法签名从 `@Param('userId') userId: string` 改为 `@Param() params: GetUserParamDto`，并移除手工 `+userId` 转换。

   * 对应补齐 swagger 的参数描述（如需要，将加 `@ApiParam({ name, example })`，确保文档完整）。

统一响应文档（可选但推荐）

将现有 `@ApiSwaggerResponse({ status, description })` 统一补上 `type: ApiResponse`，让 Swagger 显示统一响应结构（不改变运行时返回）。

## 影响评估

* 路由 URL 不变；主要是参数校验更严格、Swagger 文档更完整。

* `/auth/list` 仅补齐 Swagger 与安全标记；接口鉴权逻辑不改（仍需 token），因此与现有 e2e 行为一致。

## 验证方式

* 运行单测/端到端测试，重点覆盖：

  * `GET /auth/list`：无 token 401、有 token 200。

  * 任一详情接口（如 `/system/user/:userId`）：参数非法时返回 400，合法时行为不变。

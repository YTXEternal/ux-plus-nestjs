## 现状梳理
- 项目所有接口实际基础路径为 `/api/v1/...`（全局前缀 `/api` + URI 版本 v1）。
- 全局守卫依次为 CPU 过载保护 → Token 鉴权 → 权限校验；其中权限校验支持 `SUPERADMIN` 角色自动拥有 `*:*:*`（通行所有 `@RequirePermissions` 接口）。
- 当前 [app.e2e-spec.ts](file:///d:/data/development/Projects/NestJS_React_StoreManagement/ux-plus-nestjs/test/app.e2e-spec.ts) 存在 `sequelize.sync({ force: true })`，一旦指向非测试库会直接清库，必须加安全闸。

## 数据安全策略（保证不损坏“当前数据库”）
- 在 e2e 用例启动前做强校验：
  - 强制 `process.env.NODE_ENV = 'test'`（确保 `.env.test` 优先加载）。
  - 强制校验 `MYSQL_DATABASE === 'platform_test'`（或至少包含 `_test` 后缀）；否则直接 `throw` 终止测试，避免误连生产/开发库。
- 不再使用“全量清库/force sync”作为默认策略：
  - 改为“仅删除本次测试创建的数据”（通过 `testRunId` 前缀命名 + 记录创建的主键列表），保证即便测试库里已有数据也不破坏。
- 为避免守卫偶发丢弃请求（极端过载场景），测试启动前设置 `CPU_BASE_PROBABILITY='0'`，让 CPU 守卫永远放行（仅影响测试进程）。

## 测试覆盖策略（覆盖所有接口且保证稳定）
- 在 [test/app.e2e-spec.ts](file:///d:/data/development/Projects/NestJS_React_StoreManagement/ux-plus-nestjs/test/app.e2e-spec.ts) 内扩展为“按模块分组”的全接口 e2e：
  - 认证管理：`POST /auth/login`（成功/失败）、`GET /auth/list`
  - 系统监控：登录日志（list/delete/clean/unlock）、在线用户（list/forceLogout）、操作日志（list/delete/clean）
  - 系统管理：用户、角色、部门、岗位、菜单、字典(type/data)、参数配置、通知公告的 list/detail + 增删改接口
- 鉴权/权限：
  - 通过数据库种子创建一个 `role_key=SUPERADMIN` 的角色，并绑定一个测试用户；登录拿到 token 后统一带 `Authorization: Bearer <token>` 调用所有受保护接口。
  - 对需要 token 的接口额外覆盖“无 token → 401”的基本健壮性校验（仅挑 1~2 个代表接口，不把测试时间拉爆）。
- 断言规范：
  - 所有接口都断言返回结构 `{ code, message, data }`，并对关键字段进行最小必要校验（例如 list 返回 `data.list`/分页结构、detail 返回存在主键字段、写接口返回成功码）。

## 测试数据构造与清理（自给自足）
- 生成 `testRunId`（随机字符串）并将所有创建数据带上唯一前缀：

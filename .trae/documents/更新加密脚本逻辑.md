# 更新加密脚本计划

我将更新 `scripts/encryptPassword.js`，使其逻辑与 `UxPasswordService.encryptedPassword` 方法保持一致。

## 逻辑分析
`UxPasswordService.encryptedPassword` 的实现逻辑如下：
1.  **MD5 哈希**：先对明文密码进行 MD5 哈希处理 (`md5(plainText)`).
2.  **RSA 加密**：然后对 MD5 哈希值进行 RSA 加密。

目前的 `scripts/encryptPassword.js` 直接对明文密码进行了 RSA 加密，缺少了 MD5 这一步。

## 更新内容
1.  引入 `crypto` 模块（已有）。
2.  实现一个简单的 `md5` 函数（参考 `src/tools/md5.ts`）。
3.  在 RSA 加密前，先调用 `md5` 函数处理输入的密码。

## 执行步骤
1.  使用 `Write` 工具重写 `scripts/encryptPassword.js` 文件。
2.  使用 `RunCommand` 运行脚本测试加密结果。

## 验证
运行脚本生成的密文，经后端解密后应得到密码的 MD5 值，这符合 `UxPasswordService` 的设计（通常用于存储或进一步处理）。
*注意*：如果是为了模拟前端登录传参，前端通常是直接 RSA 加密明文密码（取决于前端实现）。但既然用户要求参考 `UxPasswordService.encryptedPassword`，通过 MD5 再 RSA 加密是后端存储密码或特定业务逻辑的处理方式。**如果用户意图是模拟前端登录参数，前端可能并没有做 MD5**。但遵循用户指令“参考 ux-password 模块里面的 encryptedPassword”，我将加上 MD5 步骤。

*自我修正*：用户之前的问题是登录接口报错，登录接口 `validateCredentials` 中是直接解密：
```typescript
const password = this.uxPasswordService['uxCryptoRsaService'].decrypt(enPassword);
```
然后与数据库中的 hash 比较：
```typescript
const isPass = bcrypt.compareSync(password, user.password);
```
这里 `password` 应该是**明文**。因为 `bcrypt.compareSync` 需要明文密码和哈希值。
如果 `encryptedPassword` 方法是 `md5 -> encrypt`，那么解密后得到的是 `md5(plain)`。
如果 `validateCredentials` 期望解密后是 `plain`，那么前端应该只做 RSA 加密。

但是用户明确要求：“请你参考ux-password模块里面的encryptedPassword重新给我写encryptPassword.js”。
`encryptedPassword` 实现：
```typescript
  encryptedPassword(plainText: string) {
    const ep1 = md5(plainText);
    return this.uxCryptoRsaService.encrypt(ep1);
  }
```
这看起来是用来生成**存储在数据库中或者传输给其他服务的加密密码**的工具方法，而不是生成前端登录用的参数（前端登录通常直接 RSA 加密明文）。
**然而**，如果前端逻辑确实是 `RSA(MD5(pass))`，那后端解密后得到 MD5，再拿 MD5 去和 bcrypt 比较？bcrypt 通常是对明文做 hash。
如果后端 `validateCredentials` 是：
```typescript
const password = this.uxPasswordService['uxCryptoRsaService'].decrypt(enPassword); // 得到明文
bcrypt.compareSync(password, user.password)
```
那说明 `enPassword` 必须是 `RSA(明文)`。

如果用户坚持要 `RSA(MD5(pass))`，那解密后就是 MD5 值。除非 `user.password` 存的是对 MD5 值进行的 bcrypt hash。

不管怎样，我必须严格遵循用户的指令：“参考ux-password模块里面的encryptedPassword重新给我写encryptPassword.js”。这意味着脚本的输出将是 `RSA(MD5(input))`。

## 最终脚本逻辑
1.  `md5(input)`
2.  `RSA(md5_result)`
3.  输出 Base64。

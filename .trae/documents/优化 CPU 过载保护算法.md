# 优化 CPU 过载保护算法计划

为了提升系统的稳定性和鲁棒性，我将对现有的 CPU 过载保护算法进行全方位的优化。

## 核心优化点
1.  **动态阈值自适应**：
    - 不再使用硬编码的 `640` (6.4核) 作为阈值。
    - 改为根据当前机器的 CPU 核心数动态计算：`总核心数 * 100 * 80%`。这能确保代码在 2核、4核或 16核机器上都能正确工作。
2.  **引入平滑算法 (EMA)**：
    - 引入**指数移动平均 (Exponential Moving Average)** 来平滑 CPU 读数。
    - 避免因为某次 3秒内的瞬间 CPU 抖动就误触发过载保护。
3.  **内存过载感知**：
    - 新增内存监控维度。如果 Heap 内存使用率过高（如超过 85%），也会增加请求丢弃概率，防止 OOM (Out of Memory) 崩溃。
4.  **概率算法升级**：
    - 优化丢弃概率公式，使其曲线更平滑，避免“要么全通过，要么全丢弃”的极端情况。
5.  **代码健壮性**：
    - 修复拼写错误 (`destory` -> `onModuleDestroy`)。
    - 完善资源清理逻辑。
    - 增加关键状态变化的日志记录（进入过载/恢复正常）。

## 修改文件

2.  `src/modules/cpu-overload-protection/cpu-overload-protection.service.spec.ts`: 更新单元测试以匹配新逻辑（尤其是动态阈值和 Mock）。

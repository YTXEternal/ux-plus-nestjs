# 认证模块升级计划：Refresh Token 实现

根据您的需求，我将为系统添加 Refresh Token 机制，实现 Token 的无感刷新。

## 1. 核心配置与服务升级
### 1.1 环境变量配置
- 在 `.env`, `.env.development`, `.env.production` 中添加 `JWT_REFRESH_TOKEN_EXPIRES` 配置。
- 默认值设置为 `3d` (3天)。

### 1.2 JWT 服务增强 (`UxJwtService`)
- **新增 Subject**: 定义 `refreshTokenSubject = 'nestjs-refresh-token'` 以区分 Access Token。
- **新增方法**:
  - `refreshToken(payload)`: 用于签发 Refresh Token，使用新的过期时间配置。
  - `parseRefreshToken(token)`: 用于验证 Refresh Token 的合法性。

## 2. 接口层改造
### 2.1 登录接口升级 (`AuthController.login`)
- **变更**: 在原有返回 `token` 的基础上，增加 `refreshToken` 字段。
- **逻辑**: 登录成功后同时签发双 Token。

### 2.2 新增刷新接口 (`AuthController.refresh`)
- **路径**: `/auth/refresh`
- **方法**: `POST`
- **权限**: 使用 `@Public()` 装饰器，跳过 RBAC 和 Access Token 校验。
- **参数**: 接收 `RefreshTokenDto` (包含 `refreshToken` 字段)。
- **逻辑**:
  1. 解析并校验 `refreshToken` 的有效性。
  2. 如果校验通过，提取用户信息。
  3. 重新生成新的 Access Token。
  4. 返回 `{ token: string }`。

## 3. 数据传输对象 (DTO) 更新
- **更新 `LoginResponseDto`**: 增加 `refreshToken` 字段说明。
- **新增 `RefreshTokenDto`**: 定义刷新接口的请求参数结构。
- **新增 `RefreshTokenResult`**: 定义刷新接口的响应结构用于 Swagger 文档。

## 4. 验证计划
1. **登录测试**: 请求 `/auth/login`，确认响应中包含 `refreshToken`。
2. **刷新测试**: 使用获取到的 `refreshToken` 请求 `/auth/refresh`，确认能获取到新的有效 Access Token。
